# 部署说明

本文件是**通用模板**：所有 IP、端口、别名都是占位符，替换成你自己的即可。
真实的服务器地址与口令见仓库根目录 `开发指南.md`（该文件已被 `.gitignore` 排除，不会公开）。

## 服务器事实（示例）

- 免密登录：先在本机 `~/.ssh/config` 里加一段别名，然后 `ssh <你的别名>`
  ```
  Host classcheckin
      HostName <公网IP>
      Port 22
      User root
      IdentityFile ~/.ssh/<你的私钥>
  ```
- 系统：Debian 12 bookworm / 2 核 / 4GB / 26GB 可用 / Python 3.11.2
- 无 iptables / nftables / ufw（入站只靠控制面板的 NAT 端口映射）

## 端口映射

| 用途 | 外网端口 | 内网端口 | 协议 | 说明 |
|---|---|---|---|---|
| 签到系统（HTTP + WebSocket） | <外网端口> | 18100 | TCP | 必填 |
| 签到系统 HTTPS（网页端定位签到） | <另一个外网端口> | 18101 | TCP | 走下面的 HTTPS 一节；用不到就别开 |

> 面板的“自定义”类型 = 同一个外网端口同时转发 TCP 和 UDP。
> 本系统 HTTP 与 WebSocket 都跑在 TCP 上，**只需要 TCP**。
> UDP 映射对本项目没有用处。
> 想换端口，只要改 `/etc/systemd/system/class-checkin.service` 里的 `CHECKIN_PORT`
> 并把面板映射的内网端口指向它即可。

## systemd 服务

```bash
systemctl status class-checkin
systemctl restart class-checkin
journalctl -u class-checkin -n 50        # 或直接看 /opt/class-checkin/data/server.log
```

服务文件：`/etc/systemd/system/class-checkin.service`

```ini
[Service]
WorkingDirectory=/opt/class-checkin/server
Environment=CHECKIN_PORT=<内网端口>
Environment=CHECKIN_DATA=/opt/class-checkin/data
Environment=CHECKIN_WEB=/opt/class-checkin/web
ExecStart=/usr/bin/python3 /opt/class-checkin/server/app.py
Restart=always
```

## 首次部署做了什么

1. 打包本地 `server/ web/ tests/ tools/` 上传到 `/opt/class-checkin`
2. 写 systemd 单元并 `enable --now`
3. 首次启动自动建库并生成初始账号，写入 `/opt/class-checkin/data/初始账号.txt`
4. 用 `tools/provision.py` 批量开号（名单示例见 `docs/账号表.example.csv`）

# 改完代码后

## 网页端 HTTPS（定位签到必需）

浏览器只在**安全上下文**里给 `navigator.geolocation`：`http://` 的页面一律拿不到定位，
所以网页端（含 iOS / 鸿蒙浏览器）要定位签到就必须走 HTTPS。安卓客户端有原生定位桥，不受影响。

一条命令搞定（在服务器上，脚本在仓库 `deploy/https_setup.sh`）：

```bash
# 参数：对外地址 对外HTTPS端口 [内部HTTPS端口=18101] [额外SAN] [对外HTTP端口=20318]
bash https_setup.sh 43.227.71.8 20319 18101
```

脚本做的事：
1. 自签一套 CA（10 年）+ 服务器证书（825 天，SAN 含对外 IP / 127.0.0.1 / localhost）
2. 写 systemd drop-in `/etc/systemd/system/class-checkin.service.d/tls.conf`，
   打开 `CHECKIN_TLS_PORT`（默认 18101）并设 `CHECKIN_HTTPS_ORIGIN`
3. 重启服务并自检（本机 `https://127.0.0.1:18101/api/config` 必须 200）

然后在面板里**加一条 NAT 转发**：外部端口 `20319` → 内部端口 `18101`（协议 TCP）。

### 为什么不是同一个端口
想在 18100 上按首字节区分 HTTP/HTTPS 就得把已 accept 的 socket 手工塞进 asyncio 的 SSL 传输层，
TCP 分段时 `SSLWantReadError` 会被当成致命错误直接掐断连接（10Mbps 的机器上很常见）。
多开一个端口是最稳的做法，代价就是多一条端口映射。

### 让手机不再报警告（可选但推荐）
自签证书浏览器第一次会拦一下，「高级 → 继续前往」之后 `isSecureContext` 就是 true、定位直接可用。
想彻底干净就把根证书装进系统：

1. 手机浏览器打开 `http://43.227.71.8:20318/checkin-ca.crt` 下载（这个接口是公开的）
2. 设置 → 安全 → 加密与凭据 → 安装证书 → **CA 证书** → 选择刚下载的文件
3. 再打开 `https://43.227.71.8:20319`，无警告、定位可用

### 换域名 / 加 IP
有域名（且域名解析到这台机器）后：

```bash
bash https_setup.sh checkin.example.com 20319 18101 "IP:43.227.71.8"
```
CA 会复用（装过根证书的手机不用重装），只重签服务器证书。

### 关掉 HTTPS
删掉 drop-in 再重启即可，HTTP 侧完全不受影响：

```bash
rm /etc/systemd/system/class-checkin.service.d/tls.conf && systemctl daemon-reload && systemctl restart class-checkin
```

## 备份与恢复

- 后台「高级 → 下载数据库备份」
- 或命令行：`scp <别名>:/opt/class-checkin/data/app.db .\backup.db`
- 恢复：把 app.db 传回 `/opt/class-checkin/data/` 后 `systemctl restart class-checkin`

## 排错

| 现象 | 检查 |
|---|---|
| 公网打不开 | `systemctl status class-checkin`、`ss -ltn \| grep <内网端口>`、面板映射是否生效 |
| 页面白屏 | 浏览器控制台；多半是某个 view 的模板报错 |
| WebSocket 连不上 | 反向代理若加了 Nginx 需转发 Upgrade 头；本项目直连无需额外配置 |
| 忘记管理员密码 | `ssh <别名>` 后运行 `python3 /opt/class-checkin/server/bootstrap.py`（仅当无用户时建号），或后台 SQL 控制台改 |
